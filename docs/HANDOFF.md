# K-Culture 커뮤니티 — 새 환경 작업 인수인계

작성일: 2026-10-29 (사용자 시간대: Asia/Seoul)

## 1. 지금 해야 하는 일

**시장조사부터 다시 시작하여 실제 수요, 기존 커뮤니티 트래픽과 활동, 신규 사이트의 진입 가능성을 검증한다.**

사용자의 마지막 우선순위 지시:

> 시장조사가 먼저야. 시장조사부터 하고, 트래픽이나 가능성 있는지 점검부터 해.

이 문서는 대화에서 확정된 목적·승인 범위·막힌 지점을 보존한 인수인계 기록이다. 시장조사 보고서나 시장성 검증 결과가 아니다. 현재까지 검증된 외부 시장 수치, 경쟁사 트래픽 수치, 카테고리별 수요 순위는 없다.

## 2. 프로젝트 목적

- 아이돌, 뷰티, 식문화 등을 포함한 K-Culture에 관해 한국인과 세계 각국의 사람들이 대화하는 커뮤니티를 만든다.
- 단순 콘텐츠 열람을 넘어 정보 공유, 질문과 답변, 경험 교류가 지속되는지 검증한다.
- 특정 국가, 핵심 이용자 연령, 초기 지원 언어, 수익 모델, 예산, 출시일, 기술 스택은 아직 확정하지 않았다.
- 국가·언어는 시장조사에서 비교할 대상이며 한국어·영어만 지원한다고 임의로 확정하지 않는다.

## 3. 사용자에게 승인된 범위

아래 8개 **후보 카테고리 전부**를 사용자가 승인했다. 시장성이 입증되었다는 뜻도, 전 카테고리를 동시에 출시한다는 확정도 아니다.

| 카테고리 | 조사할 수요 가설 |
| --- | --- |
| K-pop·아이돌 | 컴백·공연·팬 활동·티켓팅 정보에 따른 반복 방문과 정보 교류 |
| 뷰티·스킨케어 | 피부 고민, 제품 후기, 루틴, 국가별 구매 정보 |
| 한국 음식 | 레시피, 현지 대체 재료, 식당·마트 정보 |
| 드라마·영화 | 작품 추천과 감상, 작품 속 한국 문화 해설 |
| 한국어 | 콘텐츠 속 표현, 일상 표현, 학습·교류 |
| 한국 여행·생활 | 현지인 추천, 여행 계획, 생활 경험과 질문 |
| 패션 | 스타일, 브랜드, 사이즈, 해외 구매 정보 |

사용자는 특히 K-pop에 대해 다음 아이디어를 제시했다:

> 아이돌 티겟팅이나, 공연 정보등을 공유할 수도 있겠네. 여긴 페이지 세분화도 가능해보인다.

이 발언은 조사할 기회에 포함한다. 티켓 거래·결제·예매 대행 기능 승인이 아니다.

## 4. 반드시 지켜야 할 진행 순서

1. 시장조사 및 트래픽·신규 진입 가능성 분석을 완료한다.
2. 결과를 사용자에게 제출하여 검토받는다. 검토 전 다음 설계 단계로 넘어가지 않는다.
3. 검토된 시장조사에 근거해 게시판 목록을 만든다.
4. 화면 목록서를 만들고 사용자 피드백을 받는다.
5. 기능 목록서를 만들고 사용자 피드백을 받는다.
6. Reddit과 디시인사이드의 UI 디자인과 UX 흐름을 조사한다. 사용자는 두 사이트의 UI·UX를 먼저 클로닝한 뒤 우리 목록서에 맞춰 재조립하는 방식을 요청했다.
7. 어떤 디자인 요소를 어떻게 재조립할지 **각 건마다 사용자 승인을 받는다.** 승인 내역을 남기며 진행한다.
8. 사용자의 수동 QA 피드백을 받아 수정한다.

## 5. 시장조사의 범위와 결과물

### 확인할 질문

1. 8개 분야에 어떤 국가·지역의 수요가 있으며 관심이 유지 또는 성장하는가?
2. 관심이 실제 커뮤니티 글쓰기·댓글·질문·정보 공유로 이어지는가?
3. 기존 서비스의 트래픽과 최근 활동은 어느 정도이며 이용자는 무엇을 얻는가?
4. 기존 대형 서비스가 있는데 새 커뮤니티로 올 이유가 무엇인가?
5. 검색·팬덤·정보 공유 등 어떤 경로로 유입을 확보할 수 있는가?
6. 한국인 이용자가 참여할 동기와 해외 이용자가 재방문할 이유가 각각 있는가?
7. 어떤 카테고리부터 진입해야 하며 어떤 조건에서는 진입을 보류해야 하는가?

### 조사 방법과 해석 원칙

- 공식 조사·통계와 실제 커뮤니티 관측을 우선하고, 출처 URL·발행일·측정 기간·지역·대상·단위를 남긴다.
- 공개 트래픽 도구의 수치는 외부 추정치로 표시한다. 월 방문 횟수, 순방문자, MAU, 가입자, 구독자, 글·댓글 수는 서로 다른 지표다.
- Reddit 전체 트래픽이나 한류 콘텐츠 전체 소비 규모를 K-Culture 커뮤니티의 잠재 가입자 수로 계산하지 않는다.
- 하위 커뮤니티의 구독자 수를 활동 이용자 수로 간주하지 않는다.
- 최근 글·댓글을 표본으로 관측할 때 기간, 표본 크기, 수집 방식, 제약을 기록한다. 수집이 불가능하면 숫자를 만들지 않는다.
- 비교 가능한 기간과 지표를 사용한다. 자료마다 기간·범위가 다르면 차이를 명시한다.
- 조사 대상이 이미 한류 콘텐츠를 경험한 사람인지 확인한다. 이들의 응답을 전 세계 인구의 비율로 일반화하지 않는다.
- 국가별 언어 장벽, 기존 경쟁, 콘텐츠 공급, 번역·운영 비용, 정보 갱신 빈도도 진입 가능성 판단에 포함한다.
- 사업 규모나 신규 유입 시나리오를 계산한다면 관측값과 가정을 구분한다. 근거 없는 전환율·시장점유율·성공 확률을 사실처럼 쓰지 않는다.
- 결과는 우선 진입 분야, 보류 분야, 진입을 권하지 않는 조건과 남은 불확실성을 포함해 사용자에게 제출한다.
- 사용자 검토를 받은 뒤에만 게시판 설계로 이동한다.

### 검토할 출처 후보 — 아직 자료 본문을 확인하지 못함

- 문화체육관광부 / 한국국제문화교류진흥원: 해외 한류 실태조사 등 카테고리·국가별 관심 자료
- 한국국제교류재단: 해외 한류 현황 자료
- 한국콘텐츠진흥원: 콘텐츠 분야별 산업·해외 동향
- 식품의약품안전처: 화장품 등 관련 통계. 수출액은 커뮤니티 이용 수요의 직접 지표가 아님
- Google Trends: 상대 검색 관심 추세. 절대 검색량 또는 이용자 수가 아님
- Similarweb: 공개되는 범위의 사이트 트래픽 추정치
- Reddit의 관련 커뮤니티와 디시인사이드의 관련 갤러리: 최근 공개 활동과 이용 패턴
- 관련 전문 커뮤니티·팬 플랫폼: 조사 중 발견한 경쟁 서비스의 유입 동기와 차별화 가능성

특정 보고서 연도나 통계값은 아직 확인하지 않았다. 새 환경에서 실제 접근 가능한 최신 자료를 확인해야 한다.

## 6. 현재 막힌 부분: 외부 네트워크

### 확인된 사실

- 클라우드 환경의 네트워크 정책은 제한 모드였다.
- 환경 설정 초안에 아래 13개 도메인이 저장된 것을 도구로 확인했다.
- 사용자는 환경 설정을 완료했다고 알렸다.
- 그 후 기존 실행 환경에서 다시 확인했을 때 GitHub와 npm registry는 HTTP 200이었다.
- Google, 문체부, KOFICE, Korea.net, KOCCA, Similarweb, Reddit 접근은 프록시의 `403 Forbidden`으로 실패했다.
- `curl --head https://www.google.com`도 `CONNECT tunnel failed, response 403`이었다. 사이트 본문을 읽기 전에 프록시 터널 단계에서 차단됐다.
- 현재 인스턴스에는 새 정책이 반영되지 않았을 가능성이 있으나, 게시 실패나 사용자 설정 오류로 확정할 근거는 없다.
- 당시 사용할 수 있는 도구에는 환경 재시작·재연결 기능이나 별도 웹 검색 도구가 없었다. 새 환경의 도구 가용성은 다시 확인한다.

### 저장된 사용자 지정 허용 도메인

```text
gall.dcinside.com
investor.redditinc.com
trends.google.com
www.dcinside.com
www.google.com
www.kf.or.kr
www.kocca.kr
www.kofice.or.kr
www.korea.net
www.mcst.go.kr
www.mfds.go.kr
www.reddit.com
www.similarweb.com
```

이 목록은 기존 설정에 추가한 조사용 도메인이다. 패키지 매니저 등 플랫폼 기본 허용 목록을 대체하면 안 된다. 이 문서나 Git 커밋 자체는 환경 네트워크 설정을 적용하지 않는다. 리디렉션 대상이나 자료 다운로드 호스트가 추가로 필요하면 실제 실패 응답을 확인한 후 최소 범위로 처리한다.

### 새 환경의 첫 작업

1. 이 문서와 사용자의 최신 지시를 읽는다.
2. 사용 가능한 웹 검색·브라우저 도구를 확인한다. 있으면 공식 자료 검색에 활용한다.
3. 외부 접속을 짧게 확인하고 정상이라면 즉시 시장조사를 수행한다.
4. 계속 차단되면 현재 설정 메타데이터와 실제 실행 결과를 구분해 진단한다. 설정 저장을 무조건 반복 요청하거나, 확인하지 않은 버튼 위치를 단정하지 않는다.
5. 자료 접근이 불가능한 경우 조사 미완료라고 명시한다. 이를 이유로 화면 설계나 기능 구현을 대신 진행하지 않는다.

Python 표준 라이브러리로 가능한 최소 접속 확인 예:

```bash
python3 - <<'PY'
import urllib.request

urls = [
    'https://github.com',
    'https://www.google.com',
    'https://www.mcst.go.kr',
    'https://www.kofice.or.kr',
    'https://www.similarweb.com/website/soompi.com/',
    'https://www.reddit.com/r/kpop/about.json',
]
for url in urls:
    try:
        request = urllib.request.Request(url, headers={'User-Agent': 'Mozilla/5.0'})
        with urllib.request.urlopen(request, timeout=15) as response:
            print(url, response.status)
    except Exception as error:
        print(url, type(error).__name__, str(error))
PY
```

접속 성공만으로 자료 수집·트래픽 분석을 완료했다고 하지 않는다. 프록시 차단과 사이트 자체의 봇 차단도 구분한다. 필요한 인증 정보는 환경 설정을 사용하고 토큰·비밀번호를 Git이나 채팅에 기록하지 않는다.
